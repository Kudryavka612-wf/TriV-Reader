# TriV-Reader

PySide6 + PyMuPDF 製の自作 PDF ビューワー / エディタ（Windows）。

閲覧・連続スクロール・回転・注釈（ハイライト/ペン/図形/テキスト/付箋/下線/取消線/墨消し）・
ページ操作（分割/統合/抽出/削除/並べ替え/白紙挿入/複製/トリミング）・しおり・検索・
ページ番号・透かし・ヘッダー/フッター・OCR・画像変換・圧縮・パスワード保護・タブ表示・
ダーク/ライト・ポータブル対応・自動更新 などに対応。

- 設定ダイアログ（`Ctrl+,` / リボンの「設定」）に全般・表示・注釈・保存・更新・
  詳細をまとめてあります。起動時の復元、注釈の既定スタイルと作成者名、保存時の
  バックアップ、自動保存などもここから。
- 見た目は配色トークン 1 か所（`viewer/theme.py`）で管理しています。ライト/
  ダークともリボン・タブ・メニュー・入力欄まで一括で切り替わり、ダークでは
  Windows のタイトルバーも黒くなります。ページには落ち影が付き、余白の色と
  「紙」の色もテーマ連動です。
- 起動直後の画面には最近使ったファイルが並び、1 クリックで開き直せます。
- `Ctrl+Z` は注釈だけでなく、ページの削除・並べ替え・回転・トリミング・
  白紙挿入・複製・墨消しの適用も戻せます（まとめて回した場合も 1 回で戻ります）。
  ボタンには次に戻る操作名が出ます。
- ファイルごとに最後に見ていたページを憶えています。開いたときは先頭のまま、
  ページの上に「前回は N ページ目まで見ていました［続きから表示］」を出すので、
  続きを読みたいときだけ 1 クリックで飛べます（勝手には飛びません）。
  設定 > 全般 > 前回見ていたページ で「自動で続きから」「常に先頭から」にも
  できます。
- PDF を開いたときの表示（幅に合わせる / 縦に合わせる / 前回の倍率 / 固定の %）は
  リボンの「ホーム」→「開いた時の倍率 ▾」か、設定 > 表示 で決められます。
- エクスプローラーから PDF を開くと、トレイに常駐中や最小化中でもウィンドウが
  前面に出ます（後ろに隠れたまま開かない）。
- テキストの挿入: 注釈 → テキストを選び、書きたい所をクリックしてそのまま
  打てます（打った分だけ欄が広がる）。ドラッグすると幅を決めて折り返す欄に
  なります。入力中の見た目のまま（同じ位置・同じ改行で）確定し、句読点の無い
  日本語も枠の右で切れません。Esc・Ctrl+Enter・枠の外のクリックで確定します。
  入れた文字はテキストツールのクリックかダブルクリックでその場で直せ、全部
  消して確定すると注釈ごと消えます。
- 注釈の色は「文字・図形・ペン」（既定は黒）と「ハイライト」（既定は黄）で別々に
  持ちます。色ボタンは選んでいるツールの方を変えます（設定 > 注釈 で既定も変更可）。
- 注釈は形どおりに掴みます。線は線の近く、塗りの無い四角・円は枠線の上だけで
  当たるので、その内側の文字はそのまま選べます。少し手が動いただけでは注釈は
  ずれません。ハイライトは 1 文字単位で、なぞっている間に塗られる文字が見えます。
  ハイライトの上をドラッグすると、その下の文字を選びます。
- PDF はまとめてドラッグ&ドロップできます（落とした数だけタブで開きます）。
- 上書き保存が弾かれても（ほかのアプリが開いている・同期中など）、開いている
  文書と未保存の編集はそのまま残ります。理由を日本語で表示し、そのまま
  別名保存に逃がせます。
- 圧縮（リボンの「保護」→ 圧縮、または ファイル メニュー）は埋め込み画像を
  指定した解像度まで縮小して入れ直します。スキャン PDF が数分の一になります。
  文字や図形はそのまま残るので、検索・コピー・注釈・しおりは保たれます。
  高画質(200dpi) / 標準(150dpi) / 最小(96dpi) / 無劣化 から選べ、「試算」で
  圧縮後のサイズを確認してから保存できます。同じ設定でそのまま保存すれば
  試算の結果を使うので、二度待たされません。保存後はその場で開いて仕上がりを
  確かめられます。画像が既に小さい PDF では
  何もせず元のサイズのままにします（太らせない）。
- 印刷はベクター出力が既定です。プリンタの解像度でそのまま出るので文字がくっきり
  します（図版が崩れる PDF 向けに画像化 300/600dpi も選べます）。
  用紙（プリンター既定 / A4 などの指定 / PDF のページサイズに合わせる）・両面・
  部ごとの丁合い・割り付け（2/4/6/9 ページ/枚）も選べます。両面に対応していない
  プリンターでは「奇数ページのみ」→ 裏返して「偶数ページのみ」で手差し両面が
  できます（「逆順に印刷」も併用できます）。ページ指定欄に打ち始めると自動で
  そのラジオが選ばれ、書き方が誤っていれば印刷ボタンが押せなくなります。
  プレビューはダイアログを広げたぶん大きくなります。注釈のチェックを
  外すと「文書のみ」で刷れます（フォームに入力した値は残ります）。「PDF のページサイズに合わせる」は B5 の届出書や
  はがきが混ざった束をそのまま刷るときに使います。プレビューは選んだ用紙と
  余白（点線）どおりに出るので、刷ってから切れているのに気づくことがありません。
- マウスジェスチャー: ページの上で右ボタンを押しながら
  ↓ タブを閉じる / ← 前のタブ / → 次のタブ / ↑ 先頭ページ。
  割り当ては設定から変えられます。
- 中ボタンを押すとオートスクロール（上下左右）。もう一度押すと止まります。
- ページ内のリンクはクリックで辿れます。目次や「○ページ参照」のジャンプは
  そのページへ、URL は既定のブラウザーで開きます（マウスを載せると行き先が
  ステータスバーに出ます）。飛んだあとは `Alt+←` で元の位置へ戻れ、`Alt+→` で
  また進めます。しおりからのジャンプも同じ履歴に入ります。
- スナップショット（注釈タブの「スナップショット」）: 範囲をドラッグすると、その
  部分を 200dpi の画像としてクリップボードへ入れます。Word やメールにそのまま
  貼れます。右クリックの「このページを画像としてコピー」でページ全体も取れます。
- 「注釈・入力値を固定して保存」（リボンの「保護」→ 配布用、または ファイル
  メニュー）は、注釈やフォームの入力値をページの絵の一部にして別名保存します。
  相手に渡しても動かされたり書き換えられたりしない、控え・確定版を作る用途です。
- `F11` で全画面（リボン・パネル・ステータスバーを隠す）。`Esc` で戻ります。
- `F1` で、使えるキーボードショートカットの一覧が出ます。
- タブを右クリックすると、そのファイルをエクスプローラーで表示・パスをコピー・
  他のタブをすべて閉じる、ができます。中ボタンクリックでタブを閉じられます。
  長いファイル名は中央を「…」で詰めて先頭と拡張子を残します（マウスを載せると
  フルパスが出ます）。
- 文字選択はページをまたいでドラッグでき、`Ctrl+A` で文書全体を選べます。
  ダブルクリックで語、トリプルクリックで行。右クリックからコピー・ハイライト・
  下線・取消線・選択文字列で検索ができます。

## 不具合が起きたとき
- 予期しないエラーは `%LOCALAPPDATA%\trivreader\logs\error.log` に記録され、
  画面にも短く出ます（ヘルプ > エラーログを開く）。アプリ/Python/PyMuPDF の
  版数も一緒に残るので、そのまま報告に使えます。

## 速度について
- ページの描画結果はメモリにキャッシュ（既定 128MB・古い順に破棄）します。
  一度見たページへ戻るときは描き直しません。スクロールが止まると前後の
  ページを先読みします。
- サムネイルは見えている範囲（＋前後6行）だけを描き、離れた行の画像は捨てます。
  300 ページのスキャン PDF を開いても、裏で全ページを描き続けません。
- 入力欄が数百ある官公庁フォームは、欄の生成と未対応機能の走査を最初の
  描画のあとに回しています（開いた瞬間に固まらない）。
- 中身を変えたときは必ずキャッシュを捨てるので、古い絵が残ることはありません
  （`render_cache_test.py` で検証）。

## 実行（ソースから）
```powershell
pip install -r requirements.txt
python main.py
```

## ビルド / 配布 / 自動更新
[BUILD.md](BUILD.md) を参照。

- 通常ビルド: `python build_exe.py`
- 軽量版（OCRなし）: `python build_exe.py --lite`
- ポータブル版: `python build_exe.py --portable`
- 1コマンド公開（要 GitHub CLI）: `python release.py --notes "更新内容"`

## 自動リリース（GitHub Actions）
`viewer/version.py` の `APP_VERSION` を上げてコミットし、`vX.Y.Z` タグを push すると
クラウドで自動ビルドされ、GitHub Releases に公開されます（`.github/workflows/release.yml`）。

タグは**注釈付き**（`-m` 付き）にしてください。そのメッセージがそのまま
リリースノートになり、`update.json` にも入ります＝アプリの「更新を確認」で
利用者に見える文面になります。

```powershell
git tag -a v1.6.0 -m "v1.6.0
・○○を追加
・△△の不具合を修正"
git push origin v1.6.0
```

`-m` の無い軽量タグで push した場合はタグ名だけが出ます（コミットメッセージが
そのまま出ることはありません）。
